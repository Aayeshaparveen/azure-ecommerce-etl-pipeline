# Azure E-commerce ETL Pipeline

A beginner-friendly Data Engineering portfolio project that ingests sample e-commerce sales data, cleans and validates it with Python/pandas, and produces Silver and Gold CSV outputs. It is designed to be extended with Azure Data Lake Storage Gen2 and Azure Data Factory.

## Architecture

CSV source (Bronze/raw) -> Python ETL -> cleaned Silver CSV -> daily Gold sales summary

## Technologies

- Python and pandas for ETL
- SQL for analytical aggregation examples
- pytest for unit tests
- Git and GitHub for version control
- Azure Data Lake Storage Gen2 and Azure Data Factory (planned cloud integration)

## Project structure

- `data/raw/`: synthetic source data
- `data/silver/`: cleaned output generated by the ETL
- `data/gold/`: daily revenue summary generated by the ETL
- `src/transform_sales.py`: transformation logic
- `sql/sales_summary.sql`: example SQL aggregation
- `tests/`: automated tests

## Run locally

Python 3.10+ recommended.

### Windows PowerShell

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/transform_sales.py
python -m pytest
```

If PowerShell blocks activation, use Command Prompt and run `.venv\\Scripts\\activate.bat`, or invoke `.venv\\Scripts\\python.exe` directly.

## Data quality rules

- Keep one row per `order_id` (first occurrence wins).
- Parse dates and numeric fields; discard rows with invalid required values.
- Require quantity greater than zero and unit price greater than or equal to zero.
- Calculate `total_sales = quantity * unit_price`.
- Aggregate daily revenue, distinct order count and units sold.

## Azure extension plan

1. Create a resource group and private Storage Account with hierarchical namespace enabled, after checking current pricing and free-tier eligibility.
2. Upload the raw sample CSV to a `raw/` path in a Data Lake container.
3. Configure an Azure Data Factory linked service and dataset for the storage account.
4. Create and test a Copy Data pipeline to move the source into the lake.
5. Decide where Python transformations will execute (for example, locally for the first version or on a suitable compute service for a cloud version).
6. Store exported ADF pipeline definitions in `adf/` and document the deployment process.

## Security and cost

- Do not commit passwords, account keys, connection strings, access tokens or `.env` files.
- Keep storage private and use least-privilege access.
- Azure services may incur charges. Check the pricing for your subscription before deploying, and delete resources when finished if they are no longer needed.
- The sample data is synthetic.

## Limitations

This starter version runs locally; it does not yet connect to Azure or deploy an ADF pipeline. The SQL file is an example query and requires the Silver CSV to be loaded into a SQL table before execution.
